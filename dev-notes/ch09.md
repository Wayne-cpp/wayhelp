## 2026-10-09 · Spec 评审(GPT 复审,用户采纳修订)

**我的关键原话**:「我先用gpt review一遍」→「spec已经使用gpt修改了」

**关键产出**:
- 修订后 spec(同路径,工作区直接改);四处实质加固:
  1. Langfuse v3 补 MinIO 对象存储(我漏了);trace 跨 resume/重启续传(turn_message_id/trace_id 持久化进 state,resume 从 checkpoint 重建,归原意图);检索/工具/MCP 在固定边界补 SDK span(CallbackHandler 抓不到普通 Python 调用)
  2. 反馈契约重做:SSE 新增 `turn_committed` 帧发 `assistant_message_id`(前端不再算 reply_index,BIGINT 用字符串防精度丢失);新增 `chat_feedback` 表持久幂等(唯一键 (conversation_id, assistant_message_id),up/down 都落);先校验账本再回捞 checkpoint,禁止在累积 messages 按包含关系定位(会串轮)
  3. 飞轮从 ensure_future 改成 lifespan 单 worker + asyncio.Event 唤醒 + DB 退避(lcq 加 process_status/attempt_count/next_attempt_at/last_error,指数退避,到限 failed 人工重试)——原方案退避到期无人唤醒,真坑
  4. 审核写回事务化:review_queue 加「写入中」状态+冻结事务+知识库全局作业锁(ingest/vectorize/reset/rebuild/manual_ingest 全互斥);full rebuild 从 review_queue 重放已核准 FAQ;eval_runs 加 run_id 幂等+语料/评估集 SHA-256 版本,趋势只连同版本轮次;评估语料固定 knowledge_docs 基线,飞轮闭环独立验收

**拒绝/纠偏**:GPT 否掉我三处——①「图编译时挂一次回调」改成按请求工厂创建+关闭 flush,resume 显式重建 trace context;②ensure_future 飞轮触发改成 worker+退避唤醒;③approve 直接调 manual_ingest 改成冻结事务+写入中状态+全局知识库锁(manual_ingest 契约不支持 category/content_type,不能直接用)

**翻车与返工**:用户提供的 `sql/ch09-ddl.sql` 因此落后 spec——缺 chat_feedback 整表、review_queue 写入中状态与 approved_at/knowledge_chunk_ids/last_write_error、lcq 六新列、eval_runs 四新列;已声明以 spec §6 为准,实现计划第一个任务就是重写该 DDL 并同步 db/init/07-ddl.sql
