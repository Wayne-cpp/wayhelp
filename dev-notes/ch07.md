## 2026-09-22 brainstorm 定稿

- **我的关键原话**:「用 Superpowers 模式让客服在一通会话里记得住前面聊过什么,把第一版的简单裁剪升级成正经的上下文管理。只管当前会话,不跨会话、不存用户画像」;三层结构「最近的留原文……中间一层按规则截短……最远的异步压成一段段梗概」「降级只挪这两个 id、不搬数据」;摘要「触发看用量不数条数,工具结果压根不落消息表」;「梗概不许单独占一条 system」;token 预算「从模型窗口倒推,不写死成常量」;验收给了演示配置与三个预算数(滑窗 5650、层1 3954、层2 1695)。
- **关键产出**:路径裁定 Architectural;探索报告(现役裁剪落点 nodes.py:122 _history_turns 按轮截无预算 / tool_chat_chain.py:140 fit_tool_context 丢最旧轮;ch07 DDL 已备好但三处接线缺:DDL_PAIRS、db/init/05、dbfixtures);四节设计逐节获确认(架构与时序 / 预算公式与口径 / 摘要任务+拼装顺序+日志 / 接口+前端+测试策略)。
- **我拒绝或纠偏了什么**:①落库口径提问后拍板「停写 tool 结果行」(assistant 保留 tool_calls 元数据),_to_stored 的 envelope 行为要改、有测试要跟着改;②数据流三选一拍板「checkpoint 供数据 + MySQL 供锚点」,否掉 MySQL snapshot(层2 tool 截短会成死规则)与锚点镜像进 state(异步任务碰 checkpoint 无谓耦合)。
- **翻车与返工**:第 2 节梗概预留按单段估 300 token,第 3 节发现投影是「最近几段拼接」,订正为 3 段 ≈650 token,差额从安全余量扣,验收三数不变——已在第 3 节自认并获确认。
