## 阶段 2:Spec 复审修订(2026-09-10)

**用户关键原话**
- 「spec我使用gpt6 review修改了」——spec 经 GPT-6 复审修订(233 行新增/122 行删除),用户同时把手写 DDL 落到仓库 `sql/ch02-ddl.sql`。

**复审主要修订(GPT-6 稿并入)**
- 请求协议新增匿名 `user_id`(浏览器 `crypto.randomUUID()` + localStorage),会话核对 user+session 双因子,但明确不构成身份认证
- `session_id` 请求层接受两种规范形式:正十进制数字串(DB adapter)/ 规范 UUID(内存 adapter),各自只认自己创建的
- 新增 `AppRuntime` 依赖注入:`create_app(settings, model, runtime)`,生产路径才建 engine+ping;启动改 `uvicorn --factory`,删掉模块级 `create_app()` 导入即连库的副作用
- 工具结果落库格式:DDL 没有工具状态字段,tool 行 content 存 JSON envelope `{"v":1,"ok":...}`;assistant 行 tool_calls 只存 name/args/id/type
- `create_ticket` 独立事务:同事务更新 conversation 状态为「已转人工」,不用 wait_for、不自动重试(写副作用不可复制);只有只读工具享受超时重试;工单号格式 T+UTC 时间戳+12 位随机 hex
- 重试退避公式定为 `0.5 * 2^(n-1)`;新增 `MAX_TOOL_CALLS_PER_TURN` / `MAX_TOOL_RESULT_CHARS` 配置与 `invalid_tool_call` / `tool_context_too_long` 错误帧
- 锁改为 `SessionLockRegistry` 懒创建(DB 会话跨重启存在,不能只在新 session 时建锁);最终 commit 用 `asyncio.shield` 保护,取消期间等事务落地才放锁
- 历史裁剪细化:按完整 turn 分组,孤儿 tool 组整体丢弃;第二次调用前重算预算
- 移除 `MAX_MESSAGES_PER_SESSION` 必须为偶数的限制;内存 Store 按完整 turn 淘汰
- 浏览器验收从 3 条加到 4 条(新增「帮我转人工」→ create_ticket + SQL 抽查)
- 测试库基建:`TEST_ADMIN_DATABASE_URL` 建/删 `wayhelp_test`,`TEST_DATABASE_URL` 跑测试;应用账号不需要 CREATE DATABASE 权限

**我的关键产出**
- 对修订稿做自审:字段/枚举/长度与 DDL 逐项一致(tool_call_id 64、ticket_no 27 ≤ 32);§7 帧顺序与 §5 envelope 无矛盾;未发现需退回的问题

**用户拒绝/纠偏**
- 我原稿的「内存实现扩展字段存不存均可」被 GPT-6 稿收紧为「与 DB 一致保存,按完整 turn 淘汰」——采纳
- 我原稿的「第二次调用不绑工具物理收敛」保留,但补上非法 tool_calls 的协议级校验(超量/重复建单/invalid_tool_calls/坏 id 一律 `invalid_tool_call` 不执行任何工具)

**翻车与返工**
- 暂无代码翻车;我原稿的两处模糊点(内存淘汰单位、锁只在创建时建)被复审抓出并修订,属计划前拦截。
