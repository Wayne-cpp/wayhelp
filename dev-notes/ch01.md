# Ch01 开发过程记录 —— 电商智能客服:纯对话阶段

## 阶段 1:Brainstorm 定稿(2026-09-09)

**用户关键原话**
- 「我要用 Superpowers 模式做一个电商智能客服系统,第一步先跑通纯对话。」
- 「模型接入直连上游,应用侧统一说 OpenAI 协议,地址、模型名、密钥全在 .env,GPT、Claude、DeepSeek、Ollama 都能换着接」
- 「本章不做:工具调用、Agent 循环,先跑通纯对话」
- 「全程走 Superpowers 流程……产出不是可单测代码的任务(纯 Prompt、数据类),把 TDD 那步换成拿标注样例或评估集跑一遍验证」
- 「涉及具体库、框架、API 的用法,一律先用 Context7 MCP 查最新官方文档和接口定义再动手,别凭记忆写」
- 「上面点名的技术选型是定死的,实现中发现矛盾或走不通,停下来问我,不要自行换方案」

**澄清问答(AskUserQuestion 四连)**
- Python 环境:系统 Python 3.7.3 太老 → 用户选「uv 建 3.12 虚拟环境」
- 聊天页面 → 用户选「不要,curl 验收即可」(工作要求里提的 Vibe Coding 页面本章不做)
- 会话存储 → 用户选「进程内存 dict」,接口预留可替换
- 结构化字段 → 用户确认默认方案:order_id(可空)、intent(退货退款/换货/仅退款/维修/催发货/投诉/其他)、expectation(可空,全额退款/部分退款/换货/补发/维修/赔偿/其他)、summary

**我的关键产出**
- 路径分类:architectural(全新空项目)
- 方案对比:A 轻分层+LCEL(采纳)/ B RunnableWithMessageHistory(拒:历史管理耦合进 LangChain 接口,换存储多一层适配)/ C 手写 messages(拒:与定死的 LangChain 技术栈冲突)
- 设计 7 节:项目结构、对话链路(SSE)、结构化提取、System Prompt 要点、错误处理、测试与验证(TDD 变体)、验收映射
- Spec 路径:docs/superpowers/specs/2026-09-09-ecommerce-customer-service-ch01-design.md

**用户拒绝/纠偏**
- 无方案级纠偏;方案 A + 7 节设计一次通过(用户回复「ok」)。聊天页面被用户明确划出本章范围。
