## 阶段 2:Spec 复审修订(2026-09-09)

**复审发现**
- 先写入本轮 user 再通过 Prompt 追加 human,存在重复发送风险
- 会话缺少并发、上游失败和客户端断开时的完整 turn 提交语义
- “OpenAI 兼容端点均可替换”没有覆盖结构化输出方法和真实端点能力差异
- SSE 的“逐 token”承诺、分帧格式、错误收尾和取消行为不够精确
- Prompt 裁剪没有明确完整输入预算,Store 自身也没有容量上限
- 提取评估的“综合准确率”公式和样例覆盖不足

**修订决定**
- 新增 `ChatService` 协调模块,按 session 加锁,只在成功后原子提交 user/assistant
- Store 设全局 session 上限和单 session 消息上限,容量满时拒绝新 session;Ch01 明确单进程运行
- 定义兼容端点最低契约,`STRUCTURED_OUTPUT_METHOD` 限于 json_schema/json_mode,保留本章无工具调用范围;新增经 HTTP 验证的 provider smoke test
- SSE 改称文本增量,固定 session/delta/error/[DONE] 契约;提交前异常/取消不提交,提交后断开保留完整 turn
- 对完整 Prompt 使用近似 token 计数并保留 system/current,区分估算预算与真实上下文窗口;输入预检超限在创建 session 前返回 422
- 限制输入和保存的 assistant 文本长度,截断与空输出作为失败;session 容量满后需重启清空,锁表随 session 有界
- 评估集增至至少 21 条,明确逐字段、宏平均和 exact-match 公式,失败样例计错,额外报告有/无订单号分组结果
