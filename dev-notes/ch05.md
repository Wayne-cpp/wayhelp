# ch05 开发实录:LangGraph Workflow 编排骨架 + 主力 Agent

> 本章主题:Workflow 确定性编排做骨架,主力 Agent 作为骨架里的核心节点;全程走 Superpowers 流程。
> 格式约定:每个阶段记四样——我(用户)的关键原话、AI 的关键产出、我拒绝/纠偏了什么、翻车与返工。

## 阶段 1:brainstorm 定稿(2026-09-17)

**我的关键原话**(任务书要点,全文见会话):

- 「用 Superpowers 模式把客服系统升级成生产级架构:Workflow 确定性编排做骨架,主力 Agent 作为骨架里的核心节点」
- 「祛魅热身:先不用框架,手写一遍最裸的 Agent 循环……看清它就是个带工具的循环,再用 LangGraph 重构」
- 「图骨架按这条流程搭:指代消解、意图识别、按意图分流、知识检索、置信度闸、主力 Agent、日志记录」
- 「分流规则写死在代码里」;七类意图→四出口(知识类强制 RAG+置信度闸 / 业务数据类直接进 Agent / 投诉不进 Agent 给两个选项 / 闲聊固定话术)
- 「转人工、建工单是两件事,分开做,都交用户在前端自选、不后端自动执行」
- 「涉及具体库、框架、API 的用法,一律先用 Context7 MCP 查最新官方文档再动手,别凭记忆写」
- 「上面点名的技术选型是定死的,实现中发现矛盾或走不通,停下来问我,不要自行换方案」

**AI 的关键产出**:

- 探索报告:确认现有链路是手写「两次调用」编排(非 ReAct),`RetrievalTrace` 是检索→编排的桥;`create_ticket` 同事务置会话「已转人工」(与「两件事分开」冲突,设计里拆 `write_ticket` 解决);`SERVICE_SYSTEM_PROMPT` 「每轮最多一次工具」条款与 ReAct 多步冲突(设计里修订);langgraph 未装、langchain-core 已 1.6.2。
- Context7 核查(langgraph 1.0.8):StateGraph/条件边/compile(checkpointer)/get_stream_writer/stream_mode/create_react_agent 现行 API 确认可用。
- 5 个澄清问答定案(D1~D5):① 新旧链路**原地替换**;② checkpointer 用 **AsyncSqliteSaver**;③ ReAct **手写循环节点**(不用 create_react_agent 黑盒);④ 建工单走**结构化动作端点** `POST /v1/chat/action`;⑤ 热身裸循环**留档** `examples/bare_agent.py`。
- 设计 spec:`docs/superpowers/specs/2026-09-17-ch05-langgraph-workflow-design.md`(15 节,含分流写死表、State schema、ReAct 停止条件与 token 预算、SSE suggest_actions 帧、验收→测试映射)。

**我拒绝/纠偏了什么**:无。5 个分支问答用户均采纳推荐项,8 节设计一次通过(「通过,写 spec」)。

**翻车与返工**:无。探索阶段发现的两处冲突(create_ticket 置状态、prompt 条款)在进入设计前已被识别并纳入方案,未造成返工。
